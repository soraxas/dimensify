# RoboSim native restoration, 2026-10-13

## Reproduction and candidate

The old `just robosim` recipe requested `transport_udp,robot`, but the Dimensify
manifest had neither `robot` nor a registered binary. `cargo check -p dimensify
--features robot --bin robosim --offline` failed with a missing-feature error.

The candidate is the uncommitted RoboSim restoration on the revision below.
The standalone workspace resolves its dependencies in its own ignored lockfile.


The input digest covers the Dimensify manifest, lib and binary entrypoints, all
`src/robosim/*.rs`, the demo URDF, and the standalone workspace's resolved
`Cargo.lock`, with relative path plus NUL plus contents in the recorded order.
The binary is `target/debug/robosim` in this vendor workspace; dev profile,
`robot` feature. No browser artifact was built or served.
These digests describe the captured build before the subsequent cleanup of
documentation, source comments and manifest descriptions; runtime code is unchanged.

## Scene and render

- Embedded `assets/robots/demo.urdf`, all joint positions initially zero.
- Native Metal, Apple M5 Max, macOS 26.7.1; 1100 x 800 offscreen target.
- Camera frames the complete initial mesh bounds; yaw 0.65, pitch 0.35,
  distance 1.8 times the bounding-box diagonal; no pointer input injected.
- Expected: upright base and upper arm, horizontal forearm, cyan tool sphere,
  readable joint selection and keyboard/mouse instructions.
- Command from this directory's workspace root:
  `rtk just robosim --screenshot /tmp/robosim-restored.png`.
- Inspected `/tmp/robosim-restored.png`: all four meshes are visible and lit,
  orientation and controls text match the expected result. The process exits
  successfully; `/tmp/robosim-render.log` records the adapter and saved image.

## Other verification

- `rtk cargo test -p dimensify --features robot --lib`: 11 tests pass, including
  the retained compatibility-camera test. Robot checks exercise hierarchical
  motion, one coordinate conversion, joint limits, mimic and prismatic joints,
  malformed graphs, primitive dimensions, mesh errors and path resolution.
- Zero-normal STL and rotated Collada fixtures failed before the imported-normal
  correction and pass afterward. These are geometry tests, not rendered mesh
  quality comparisons.
- `rtk cargo clippy -p dimensify --features robot --lib --bin robosim -- -D warnings`
  passes. Focused rustfmt checks pass; stable rustfmt warns that the vendor's
  existing nightly-only `imports_granularity` setting is ignored.
- `rtk just robosim --check`: four visual meshes and two controllable joints.
  A custom URDF path containing spaces also passes; a missing URDF exits with
  status 1 before creating a window.
- The default Dimensify normal-dependency tree contains neither `urdf-rs` nor
  `mesh-loader`; both parsing libraries are optional.
